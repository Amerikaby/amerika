## Текущая версия — 18.10.2026

По просьбе Леонида объединены генератор, каталог и внутренние страницы Claude с выбранным светлым оформлением Codex. Продолжать в `site/`, ветка `claude/project-thread-ph3goc`. Эскиз сохранён в `design/concept-2026-10-18/` как история дизайна. Рабочая тестовая публикация — https://amerika.by/newcodex/; все разделы внутри этого префикса. `/new2/` и основной WordPress остаются отдельными версиями.

По умолчанию сборка теперь пишет в игнорируемый каталог `newcodex/`, `BASE=/newcodex/`. Для предыдущей сборки нужно явно задать `BASE=/new2/ OUT=new2`.

Светлая тема — `assets/theme.css`, добавляется к базовому CSS при сборке. Hero — `static/img/hero-light-suv.webp`, декоративная AI-иллюстрация с явной подписью. Рецепт и запрос остаются в каталоге эскиза.

Расчётное ядро `calc-core.js` отдельно возвращает `delivered`, `repair` и `total`. Итог на главной, карточках и в полном калькуляторе включает выбранный резерв восстановления и тариф; льгота по умолчанию выключена. Восстановление 1500 USD — редактируемый пример, а не оценка конкретного лота. Цены покупки в `data/home-models.json` остаются черновыми. Курсы на 18.10.2026 проверены по `https://api.nbrb.by/exrates/rates/USD?parammode=2&ondate=2026-10-18` и аналогично EUR: USD/BYN 3.0091, EUR/BYN 3.3749. Источник и дата показываются в полном расчёте. При следующем обновлении ставки нужно сверить заново.

### Приём заявок и аналитика

`CONFIG.leadEndpoint = 'api/lead.php'`. Путь разрешается относительно BASE, в том числе на вложенных страницах. `static/api/lead.php` при сборке копируется в `api/lead.php`; при размещении в `/newcodex/api/` или `/api/` ищет WordPress в одном из двух родительских каталогов и загружает его из корня и использует действующий `wp_mail`. Получатель берётся из настроек существующей формы Contact Form 7 №103 (проверено: info@amerika.by), без новых SMTP-секретов. В письме — телефон, имя, пожелания/расчёт, исходная страница и рекламные метки. Прямой интеграции с amoCRM этот обработчик не обещает.

Есть проверка согласия, нормализация телефона, ограничение длины, honeypot, подписанный токен формы с ограниченным сроком действия, ограничение частоты и повторов одного requestId. Положительный ответ — только после принятия письма почтовым транспортом WordPress. Это не подтверждение получения письма во входящих. При ошибке поля сохраняются, событие `lead_submit` не вызывается. Публичный диагностический POST, отправляющий тестовые письма, отсутствует.

Номер действующей Метрики 91733040 проверен по HTML основного сайта. Для `/newcodex/` внешняя аналитика выключена через `analytics.preview=false`, чтобы просмотры и проверки не смешивались с рекламными конверсиями; события доступны в локальном dataLayer. При сборке в корень включится существующий счётчик. Noindex сохраняется до отдельного решения о переезде.

### Проверки и публикация

`node site/tools/check-calculations.cjs` — состав суммы, изменение ремонта/тарифа, льгота, максимальная ставка по бюджету. `python site/tools/check-links.py <OUT>` — локальные страницы и якоря (скрипт рассчитан на BASE=/newcodex/). PHP проверен через `php7.4 -l`; системный `php` на Beget — устаревшая 5.6, WP-CLI использует 7.4. `check-lead.php` запускается через `wp eval-file` из закрытой папки рядом с копией `lead.php`, перехватывает `pre_wp_mail`: проверяет адаптер без реальной отправки писем.

Проверка опубликованной версии 18.10.2026: 1441 HTML-страница без битых внутренних ссылок; браузерные сценарии на ширинах 1440, 390 и 360 px прошли. Проверены перенос суммы/тарифа в заявку, совпадение быстрого и полного расчёта и обработка ошибок формы. Реальные письма при проверках не отправлялись.

Перед повторной выкладкой сравнить текущие серверные файлы с последней версией, сохранить и отдельно распаковать резервную копию. Публиковать собранный OUT целиком, включая `.htaccess` и `api/lead.php`, только в `/newcodex/`. Не переносить этот `.htaccess` в корень WordPress. Для текущего объединения резервная копия хранится вне web-корня: `/home/i/infoamvz/amerika.by/.codex-merged-20261018/before-newcodex.tar.gz`.

Перед запуском основного домена остаются бизнес-проверки: реальные цены лотов/ремонта, помеченные TODO логистические сборы и ставки мотоциклов, точная дата выпуска на границах таможенных категорий, условия для электромобилей, подтверждение доставки письма во входящие и выбранная схема amoCRM. Каталог содержит примеры из WordPress, не подтверждённый склад автомобилей. Запрос статуса по VIN готовит обращение менеджеру; автоматического доступа к системе перевозчика нет.

Статический сайт собирается одной командой из шаблонов в `site/` и данных старого WordPress
(REST API `https://amerika.by/wp-json/wp/v2/`). Зависимостей нет: нужен только Node.js 18+.

## Сборка

```bash
node site/build.mjs            # собрать в newcodex/ (данные из кеша site/cache/, если он есть)
node site/build.mjs --refresh  # заново скачать машины, статьи и марки из WordPress
```

Скрипт полностью пересоздаёт папку `newcodex/` (старые файлы удаляются), поэтому руками в `newcodex/` ничего не правим:
правки делаются в `site/` и сайт пересобирается.

Кеш JSON лежит в `site/cache/` (в git не попадает). Удалите его или запустите с `--refresh`,
чтобы подтянуть новые машины и статьи со старого сайта.

## BASE: где сайт будет жить

Все внутренние ссылки абсолютные и строятся от одной константы `BASE` в `site/build.mjs`
(по умолчанию `/newcodex/`). Её можно задать через переменную окружения:

```bash
BASE=/newcodex/ node site/build.mjs   # тест: https://amerika.by/newcodex/
BASE=/ node site/build.mjs        # корень домена: new.amerika.by или после переезда на amerika.by
OUT=/tmp/site BASE=/ node site/build.mjs   # собрать в другую папку
```

`canonical`, JSON-LD и `sitemap.xml` всегда указывают на будущие адреса `https://amerika.by/...` без тестового префикса.

`PUBLIC_URL` (по умолчанию `https://amerika.by`) — где сайт реально открыт сейчас. Из него и `BASE` собираются
абсолютные адреса `og:image` и логотипа в разметке, чтобы превью в мессенджерах работало уже на тесте.
Для поддомена: `PUBLIC_URL=https://new.amerika.by BASE=/ node site/build.mjs`.

## Адреса

Совпадают со старым сайтом, чтобы не терять позиции: каталог `/auto-usa/`, машина `/auto-usa/<slug>/`,
марка `/usa/<марка>/` (модели старого сайта `/usa/<марка>/<модель>/` → фильтр `?model=` на странице марки),
электромобили `/auto-usa/elektromobily-usa/`, блог `/blog/<slug>/`, услуги `/uslugi/...`, `/ceny/`, `/kontakty/`,
`/otzyvy/`, `/tamozhennyj-kalkulator/`, `/privacy-policy/`. Новые: `/kalkulyator/`, `/o-kompanii/`, `/uslugi/`,
`/uslugi/podbor-avto-na-aukcione/`.

`site/redirects.htaccess` — карта 301 для всех остальных адресов старого сайта (модели, Европа/Канада/Китай,
`/o-nas/`, `/faqs/`, `/instagram/` и т. д.). Генерируется при сборке из XML-карт старого сайта. В `/newcodex/` не
подключается: при переезде вставить в `.htaccess` корня перед правилами сайта.

## Выкладка

1. `node site/build.mjs`
2. Загрузить содержимое `newcodex/` на хостинг в папку `newcodex` в корне сайта (рядом с WordPress, его не трогаем).
   Удобно заархивировать `newcodex/`, загрузить архив через файловый менеджер и распаковать.
   Не забудьте скрытый файл `.htaccess`: он отключает правила WordPress внутри папки и отдаёт свою страницу 404.
3. При сборке с `BASE=/` для отдельного поддомена `.htaccess` тоже подходит. При переносе в корень amerika.by
   НЕ копируйте `.htaccess` поверх файла WordPress: перенесите нужные строки вручную.

Пока сайт тестовый: на каждой странице `noindex, nofollow`, в `robots.txt` стоит `Disallow: /`.
Перед запуском убрать `noindex` в `site/partials.mjs`, правило в `robots.txt` и заголовок `X-Robots-Tag` в генерируемом `.htaccess` (оба в `site/build.mjs`). Для preview все три ограничения сохраняются.

## Что где лежит

- `build.mjs` — сборка: загрузка данных, каталог, страницы машин и марок, блог, sitemap, 404.
- `fetch.mjs` — загрузка из WordPress REST API с кешем.
- `partials.mjs` — `<head>`, шапка, меню, подвал, форма заявки, контакты (`SITE`), пункты меню и услуги.
- `data-fixes.mjs` — ручные поправки к данным (фото, объёмы, регистр).
- `redirects.htaccess` — сгенерированная карта 301 для переезда.
- `assets/calc-core.js` — формулы калькуляторов без DOM (браузер и сборка считают одинаково).
- `pages/home.mjs` — главная (объединённая главная), `pages/calc-widget.mjs` — разметка калькулятора,
  `pages/static.mjs` — калькуляторы, услуги, цены, о компании, контакты, отзывы.
- `lib/html.mjs` — очистка HTML из WordPress (убирает обёртки, классы, span, переписывает ссылки).
- `assets/config.js` — **все ставки калькуляторов** (`CONFIG`): курсы, сборы аукциона, доставка, пошлины, утильсбор,
  блок `moto` для мотоциклов, адрес вебхука заявок `leadEndpoint`. Отсюда же строятся таблицы на странице таможенного калькулятора.
- `assets/site.js` — меню, формы, калькуляторы, фильтр каталога, галерея. При сборке склеивается с `config.js` в `newcodex/assets/site.js`.
- `assets/site.css` — общие стили.
- `pages/models.mjs` — страницы популярных моделей `/usa/<марка>/<модель>/` (Equinox, Trailblazer, Trax, Rogue, Bronco Sport, Jetta) и блок «Популярные модели» на главной и в каталоге.
  Цены рынка берутся из `data/market-avby.json`; обновить: `python3 site/tools/avby-market.py`, затем пересобрать. Новую модель добавить в `MODEL_PAGES` и в `MODELS` скрипта.

## Аналитика

`CONFIG.analytics` в `site/assets/config.js`: `gtm`, `ym`, `ga4`. Пустое значение = счётчик не загружается.
Цели (уходят в `dataLayer`, Метрику `reachGoal` и GA4 `event`): `lead_submit`, `click_phone`, `click_telegram`,
`click_viber`, `click_whatsapp`, `calc_used` (первое изменение калькулятора), `calc_send` («Получить точный расчёт»).
Метки `utm_*`, `gclid`, `yclid`, страница входа и referrer сохраняются в sessionStorage при входе и уходят в заявке.

## Фото машин

`site/data-fixes.mjs`: список машин с чужими фото (показывается заглушка), объёмы двигателей по умолчанию для
примера расчёта, правила регистра комплектаций. Превью карточки = первое фото галереи этой машины (не миниатюра 150×150).
`site/static/img/` — `og-default.jpg` (1200×630) и `logo.png` для соцсетей и разметки.

## Заявки

`CONFIG.leadEndpoint` указывает на `api/lead.php`: формы передают заявку действующему почтовому транспорту WordPress (подробнее выше). amoCRM напрямую не подключена. В заявке передаются `name`, `phone`, `car`, `source` (адрес страницы), метки рекламы, `landing`, `referrer`.
Галочка согласия по умолчанию снята и обязательна, рядом ссылка на `/privacy-policy/`.

## Исправления по трём критикам — 18.10.2026

В полном, быстром и таможенном калькуляторах пустые/отрицательные обязательные числа скрывают результат. Для ДВС и гибрида нужен положительный объём; электро выбирается явно. Проверки работают и во вкладке бюджета. Ошибка показана у поля и связана через aria-describedby. Тип двигателя остаётся доступен после выбора модели; Prius определён как гибрид, настройка переносится в полный расчёт. Старые ссылки fuel=alt поддержаны.

Карточки разделяют стоимость до Минска, условный резерв и общий итог. Подписи главной и FAQ моделей согласованы с расчётом без льготы и включённым резервом. FAQ объясняет ограничения предварительных расчётов и проверки по фотографиям без новых обязательств от имени компании.

На время отправки поля заявки блокируются и разблокируются при любом исходе; ошибка сохраняет данные. Меню удерживает фокус и временно исключает фон из взаимодействия. WordPress bootstrap поддерживает /api/ и /newcodex/api/.

Регрессии: `node site/tools/check-browser.cjs` (Playwright, Chrome; `QA_BASE` задаёт URL, NODE_PATH — установленный runtime). Все запросы форм в тесте перехвачены: реальные письма не отправляются. Проверяет некорректные значения, выбор гибрида/электро, совпадение суммы Prius, вкладку бюджета, меню, блокировку полей и сохранение заявки при сбое. Дополнительно выполнены независимые повторные проверки трёх критиков.
