# Генератор сайта amerika.by (тестовая версия /new2/)

Статический сайт собирается одной командой из шаблонов в `site/` и данных старого WordPress
(REST API `https://amerika.by/wp-json/wp/v2/`). Зависимостей нет: нужен только Node.js 18+.

## Сборка

```bash
node site/build.mjs            # собрать в new2/ (данные из кеша site/cache/, если он есть)
node site/build.mjs --refresh  # заново скачать машины, статьи и марки из WordPress
```

Скрипт полностью пересоздаёт папку `new2/` (старые файлы удаляются), поэтому руками в `new2/` ничего не правим:
правки делаются в `site/` и сайт пересобирается.

Кеш JSON лежит в `site/cache/` (в git не попадает). Удалите его или запустите с `--refresh`,
чтобы подтянуть новые машины и статьи со старого сайта.

## BASE: где сайт будет жить

Все внутренние ссылки абсолютные и строятся от одной константы `BASE` в `site/build.mjs`
(по умолчанию `/new2/`). Её можно задать через переменную окружения:

```bash
BASE=/new2/ node site/build.mjs   # тест: https://amerika.by/new2/
BASE=/ node site/build.mjs        # корень домена: new.amerika.by или после переезда на amerika.by
OUT=/tmp/site BASE=/ node site/build.mjs   # собрать в другую папку
```

`canonical`, JSON-LD и `sitemap.xml` всегда указывают на будущие адреса `https://amerika.by/...` без `/new2/`.

## Выкладка

1. `node site/build.mjs`
2. Загрузить содержимое `new2/` на хостинг в папку `new2` в корне сайта (рядом с WordPress, его не трогаем).
   Удобно заархивировать `new2/`, загрузить архив через файловый менеджер и распаковать.
   Не забудьте скрытый файл `.htaccess`: он отключает правила WordPress внутри папки и отдаёт свою страницу 404.
3. При сборке с `BASE=/` для отдельного поддомена `.htaccess` тоже подходит. При переносе в корень amerika.by
   НЕ копируйте `.htaccess` поверх файла WordPress: перенесите нужные строки вручную.

Пока сайт тестовый: на каждой странице `noindex, nofollow`, в `robots.txt` стоит `Disallow: /`.
Перед запуском убрать `noindex` в `site/partials.mjs` и правило в `robots.txt` (в `site/build.mjs`).

## Что где лежит

- `build.mjs` — сборка: загрузка данных, каталог, страницы машин и марок, блог, sitemap, 404.
- `fetch.mjs` — загрузка из WordPress REST API с кешем.
- `partials.mjs` — `<head>`, шапка, меню, подвал, форма заявки, контакты (`SITE`), пункты меню и услуги.
- `pages/home.mjs` — главная (дизайн и тексты new2), `pages/calc-widget.mjs` — разметка калькулятора,
  `pages/static.mjs` — калькуляторы, услуги, цены, о компании, контакты, отзывы.
- `lib/html.mjs` — очистка HTML из WordPress (убирает обёртки, классы, span, переписывает ссылки).
- `assets/config.js` — **все ставки калькуляторов** (`CONFIG`): курсы, сборы аукциона, доставка, пошлины, утильсбор,
  блок `moto` для мотоциклов, адрес вебхука заявок `leadEndpoint`. Отсюда же строятся таблицы на странице таможенного калькулятора.
- `assets/site.js` — меню, формы, калькуляторы, фильтр каталога, галерея. При сборке склеивается с `config.js` в `new2/assets/site.js`.
- `assets/site.css` — общие стили.

## Заявки

`CONFIG.leadEndpoint` пустой: формы работают в тестовом режиме и показывают сообщение. Когда будет вебхук amoCRM,
впишите адрес в `site/assets/config.js` и пересоберите. В заявке передаются `name`, `phone`, `car` и `source` (адрес страницы).
